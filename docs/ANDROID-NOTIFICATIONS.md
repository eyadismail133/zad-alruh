# Android Prayer Notification Integration Architecture

## 1. Overview & Architectural Boundaries

Zad Alruh implements an **Android-only**, zero-cloud, fully offline notification and alarm scheduling architecture for Islamic daily prayer times.

### Key Invariants
- **Android Platform Specific**: Only active on Android. On other platforms (iOS/macOS/Web/Linux/Windows), all operations fail closed or evaluate to inert no-ops.
- **No External Plugin Dependencies**: Does **NOT** use `flutter_local_notifications` (FLN). Directly interfaces with the native Kotlin coordinator via the dedicated Flutter `MethodChannel`:
  ```
  dev.zadalruh.zad_alruh/prayer_alarm
  ```
- **Approved Domain Planner Reuse**: Directly reuses `PrayerNotificationPlanner.build()` for generating the 10-day canonical schedule (up to 50 strictly future canonical prayer events). No duplicate calendar or horizon generation logic exists in the coordinator.
- **Single Physical OS Queue**: All physical OS mutations (`replacePlan`, `disableAlarms`, `recoverFromLatch`, `prepareReset`, `resetAll`) are serialized on a single coordinator-owned queue (`_osQueue`). Permission dialog awaits remain strictly OUTSIDE this queue.
- **Mutual Exclusion & Audio Safety**: Native `AlarmManager` triggers cooperate with process-local manual playback leases. In-app Quran recitation or adhan previews atomically suppress scheduled alarm audio into terminal `MANUAL_SUPPRESSED` delivery with a silent notice, eliminating audio overlap.
- **Privacy & Inert Startup**: Zero permission dialogs are shown upon app launch, passive startup, or app foregrounding/resume. Permission is only requested when the user explicitly toggles the notification switch in Settings.

## 2. MethodChannel Native Contract

The channel `dev.zadalruh.zad_alruh/prayer_alarm` exposes typed operations implemented in `MainActivity.kt` and `PrayerAlarmCoordinator.kt`:

| Method | Arguments | Returns | Description |
| :--- | :--- | :--- | :--- |
| `getAuthorizationToken` | none | `{"token": Long}` | Fetches current monotonic generation token. |
| `replacePlan` | `Map<String, dynamic>` | `ReplacePlanResponse` map | Replaces active plan atomically with CAS token verification. |
| `disableAlarms` | none | `DisableAlarmsResponse` map | Durably invalidates active plan and cancels AlarmManager alarms. |
| `resetAll` | none | `ResetAllResponse` map | Durably wipes active plan, ledger, and invalidates token. |
| `getState` | none | `NativeAlarmState` map | Complete native state snapshot including `pendingCleanupCount`. |
| `acquireManualPlaybackLease`| `{"requestId": String}` | `ManualPlaybackLeaseResult` map | Grants process-local lease for manual audio. |
| `releaseManualPlaybackLease`| `{"leaseToken": String}` | `{"released": Boolean}` | Releases active manual lease. |
| `stopActivePlayback` | none | `{"stopped": Boolean}` | Stops active foreground adhan playback service. |
| `canScheduleExactAlarms` | none | `Boolean` | Checks `AlarmManager.canScheduleExactAlarms()` (Android 12+). |
| `canPostNotifications` | none | `Boolean` | Checks `NotificationManager.areNotificationsEnabled()`. |
| `requestExactAlarmPermission` | none | `Boolean` | Opens system settings for exact alarm permission. |
| `requestNotificationPermission` | none | `Boolean` | Prompts `POST_NOTIFICATIONS` runtime permission dialog. |

### Strict Fail-Closed Bridge Validation
- `NativeAlarmState.fromMap`: Strictly enforces non-null, typed fields (`enabled`, `generationToken`, `canScheduleExactAlarms`, `notificationsAllowed`, `futureEventsCount`, `pendingCleanupCount`). Any negative counts, fractional tokens, or missing fields immediately throw a `NativeBridgeException`.
- `getState()` never fabricates clean `initialDisabled` states on Android failure; it fails closed and preserves error diagnostics.
- `ReplacePlanResponse`, `DisableAlarmsResponse`, and `ResetAllResponse` enforce strict consistency (e.g. `success: true` paired with `partialFailure: true` or error codes fails closed).

## 3. 10-Day Plan Generation & Truthful Metrics

The Dart coordinator calls `PrayerNotificationPlanner.build(nowUtc: _clock().toUtc(), city: city, settings: settings, generalVoiceId: voice, fajrVoiceId: fajrVoice, mode: 'full_adhan')`:
1. **Civil Horizon**: Iterates 10 consecutive civil calendar dates starting from the selected city's local civil date.
2. **Canonical Prayers Only**: Strictly evaluates Fajr, Dhuhr, Asr, Maghrib, and Isha. **Sunrise is strictly excluded**.
3. **Bound**: Retains up to 50 strictly future canonical events (`utcDateTime > nowUtc`).
4. **Deterministic Event Keys**: Formatted as `$cityId:$calculationCivilDate:$prayerKey`.
5. **Truthful Accepted Counts**:
   - `plannedFutureEventsCount`: Count of future events generated by the domain planner.
   - `acceptedScheduledCount`: Explicitly nullable (`int?`). Known ONLY when confirmed in a `replacePlan` response; on passive reads or reconcile queries, it is set to `null` to avoid falsely presenting stored counts as confirmed OS alarm registrations.
   - The UI distinguishes between exact alarms and approximate companion fallback, and never promises delivered sound.

## 4. CAS Generation Tokens & Concurrency Guarding

- Before replacing a plan, Dart requests `getAuthorizationToken()`.
- The plan is submitted with `expectedToken: currentToken`.
- If the native coordinator detects that the token changed concurrently, it returns `isStaleToken == true`.
- **CAS Invariant**: Dart **aborts the stale plan immediately** and **never** fetches a fresh token to retry the old plan.
- After every `await`, snapshot guards verify:
  1. Local `_invocationEpoch` matches the active invocation epoch.
  2. `ProgressMutationBarrier.isResetInProgress` is `false`.
  3. `ProgressMutationBarrier.currentGeneration` matches the initial generation.
  4. Preferences opt-in status and selected voices remain unchanged.
  5. `EffectivePrayerSettings` snapshot fingerprint remains identical.

## 5. Failed-Reset Recovery Latch & Confirmed Disable

To guarantee absolute data integrity and prevent orphaned alarms:
1. **Reset-Entry Hook (`executePrepareReset`)**:
   - In `PreferencesController.resetAllState()`, before manual SDK audio stop (`audioController.stop()`), Dart calls `nativeBoundary.prepareReset()`.
   - This executes on the coordinator's physical OS queue, enqueuing native `disableAlarms()`.
   - If native disable fails or reports `pendingCleanupCount > 0`, `prepareReset()` throws `NativeResetException`, immediately aborting the reset BEFORE SQLite wipe.
2. **Failure Survival**:
   - SQLite retains `notificationsEnabled == true` (no wipe occurred).
   - The native store is durably marked `enabled == false`.
3. **Container / Restart Latch**:
   - On app reboot or a fresh `ProviderContainer`, passive startup detects:
     - SQLite: `notificationsEnabled == true`
     - Native Store: `enabled == false` (or `pendingCleanupCount > 0`)
   - The coordinator enters **`PrayerNotificationStatus.recoveryRequired`**.
   - Auto-scheduling is blocked until the user explicitly taps "إعادة المحاولة والتنظيف" in Settings.
4. **Confirmed Disable**:
   - When disabling notifications, the coordinator sets state to `updating`.
   - Clean `disabled` is published ONLY upon confirmed complete cleanup with `pendingCleanupCount == 0`.
   - Native cleanup executes even if SQLite opt-out persistence encounters an error.

## 6. Permissions & Lifecycle Management

- **Passive Reads**: `reconcile({bool passive = true})` reads native state and may refresh an already enabled plan. It never opens permission dialogs; while an explicit enable/disable is in flight, passive reconciliation leaves that operation intact.
- **Listeners**: Real Riverpod listeners watch `preferencesControllerProvider` and `effectivePrayerSettingsProvider`. When settings or city change, reconcile runs passively; listeners never open system dialogs.
- **Awaited Outside Mutation Queue**: `requestNotificationPermission()` awaits outside the physical OS queue, ensuring that system dialog delays do not block other operations.
- **Cancellation While Prompt Open**: Dismissing the dialog, toggling off, or initiating a reset invalidates the invocation epoch; late permission grants cannot resurrect old enable operations.
- **Compact UI Layout**: Settings and Prayers screens are verified across compact phone dimensions (320x480 portrait and 480x320 landscape) with `textScaler: 2.0x` without layout overflows.
